### Q2. Design a three-tier architecture with a frontend, backend, and database. The backend and database must be private. How would you design the VPC and its subnets?

**A:** I would design a multi-Availability Zone VPC with separate public and private subnets.

I would create a VPC with a CIDR block such as `10.0.0.0/16` and create subnets across at least two Availability Zones.

- **Public subnets:** For Internet-facing load balancers and NAT Gateways.
- **Private application subnets:** For backend EC2 instances running containers.
- **Private database subnets:** For RDS.

The frontend should not directly expose the backend or database.

I would place an Application Load Balancer in the public subnet. It would have a public DNS name and accept HTTPS traffic on port 443. I would use ACM for the TLS certificate and Route 53 for DNS.

The backend EC2 instances would run in private application subnets without public IP addresses. I would register them in a private target group behind the load balancer.

The ALB security group would allow HTTPS traffic from the Internet, and the backend security group would allow the required application port only from the ALB security group.

For the database, I would create an RDS subnet group using private database subnets across two Availability Zones. Public access would be disabled. Its security group would allow database traffic only from the backend security group.

### Q5. What is the difference between `npm ci` and `npm install`?

**A:** `npm install` resolves dependencies using `package.json` and can update `package-lock.json`.

`npm ci` is a clean install. It requires a valid `package-lock.json` and removes the existing `node_modules` directory before installing dependencies.

### Q6. What is the difference between ENTRYPOINT and CMD in Docker?

**A:** For a production application, I would use ENTRYPOINT for the application and CMD for default arguments.

The main difference is that ENTRYPOINT defines the main executable that the container is intended to run, whereas CMD defines the default command or default arguments, which can be overridden.

### Q9. What is the difference between a DaemonSet and a StatefulSet?

**A:** A DaemonSet ensures that a copy of a pod runs on every eligible Kubernetes node that matches the selector. When a new node joins the cluster, Kubernetes automatically creates that pod on the new node.

When a node is removed, the corresponding pod is also removed.

A StatefulSet manages applications that need stable identities and stable storage.

### Q10. Can you explain Pod Disruption Budget?

**A:** A Pod Disruption Budget limits the number of application pods that can be voluntarily disrupted at the same time.

### Q11. What are the different types of Kubernetes Services from a networking perspective?

**A:** The first service is ClusterIP, which is the default type. It provides an internal virtual IP that is reachable only inside the Kubernetes cluster. It is mainly used for internal communication between services.

The second service is NodePort. It exposes the service on a static port on every worker node.

The third service is LoadBalancer, which provisions or integrates with an external cloud load balancer. In AWS, this can create an ALB through the AWS Load Balancer Controller, depending on the configuration and annotations.

### Q12. Can you explain the differences between `git reset`, `git revert`, and `git rebase`?

**A:** 

- **Git reset:** Moves the current branch pointer to another commit. It is mainly useful for local commits that have not been pushed yet.
- **Git revert:** Creates a new commit that reverses the changes from an earlier commit.
- **Git rebase:** Moves or reapplies commits on top of another branch.
