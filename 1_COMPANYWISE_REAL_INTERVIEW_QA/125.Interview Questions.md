### Q4. What are the different S3 storage classes, and when do you use them?

**A:** S3 Standard is suitable for frequently accessed data.

S3 Standard-Infrequent Access is used for data that is accessed less frequently but still requires quick retrieval.

S3 One Zone-Infrequent Access stores data in a single Availability Zone. It is less expensive but provides lower availability.

S3 Glacier is used for archived data that still requires occasional access.

S3 Glacier Deep Archive is the lowest-cost option for data that needs to be retained for a long period and is rarely accessed.

### Q7. How would you design a three-tier application in AWS?

**A:** First, I design separate web, application, and database tiers across two Availability Zones.

For the web tier, I use public subnets behind an Application Load Balancer. The load balancer accepts HTTP or HTTPS traffic and distributes requests across multiple servers or containers.

The application tier runs in private subnets across multiple Availability Zones. I use security groups to allow only the required application-port communication. Depending on the application architecture, I use Auto Scaling Groups or EKS.

The database runs in private subnets using Amazon RDS, preferably with Multi-AZ configuration. The database security group allows connections only from the application tier.

I also configure VPCs, public and private subnets, route tables, NAT Gateways, security groups, and Network ACLs. Route 53 provides DNS, and CloudFront provides edge delivery for static content.

After recovery, I run Terraform initialization, state list, and plan, and then apply changes accordingly.

### Q15. What happens if two people try to run Terraform code at the same time?

**A:** Terraform uses state locking to prevent concurrent operations. The first operation acquires the lock, and the second operation fails while the lock is held.

### Q16. What is a dynamic block in Terraform?

**A:** A dynamic block generates repeated configuration blocks from a list or map instead of writing each block manually.

It is useful when the number of blocks changes based on variables. We can use it with `for_each` to generate multiple configuration blocks.

### Q17. What is the Terraform lifecycle?

**A:** First, we run `terraform init` to initialize the Terraform configuration and backend.

Then we run `terraform plan` to review the changes Terraform will make. It provides a blueprint of the resources that will be created, updated, or removed.

Finally, we run `terraform apply` to apply the planned changes.
