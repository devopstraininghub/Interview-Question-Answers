## Q3. How would you upgrade an EKS cluster from Kubernetes 1.30 to 1.33 without downtime?
Ans: I would upgrade the cluster one minor version at a time:
1.30 to 1.31
1.31 to 1.32
1.32 to 1.33
Before upgrading, I would check deprecated APIs and compatibility with add-ons such as VPC CNI, CoreDNS, and kube-proxy.
I would upgrade the control plane first, followed by the add-ons and worker nodes.
For worker nodes, I would create a new managed node group, gradually move workloads from the old nodes to the new nodes, and monitor the application.
I would also check readiness probes, replicas, Pod Disruption Budgets, and persistent volumes to avoid downtime.
## Q4. What is the difference between Node Selector and Node Affinity?
Ans: Node Selector is used for simple node selection based on exact key-value matching.
Node Affinity provides more advanced scheduling options. It supports conditions such as In, NotIn, Exists, and DoesNotExist. It also supports required and preferred rules.
## Q5. Can you explain a real-time use case of Node Affinity?
Ans: We can use Node Affinity to prefer specific availability zones.
For example, we can configure workloads to run in availability zones ap-south-1a or ap-south-1b and allow ap-south-1c as a fallback.
## Q6. What is kube-proxy?
Ans: kube-proxy runs on every worker node in a Kubernetes cluster. It manages network rules and forwards traffic to the appropriate services using iptables or IPVS.
## Q7. What is the API Server in Kubernetes?
Ans: The API Server is the main entry point of the Kubernetes control plane. It handles API requests, performs authentication and authorization, validates requests, and updates the cluster data in etcd.
## Q8. Which deployment strategy do you use in Kubernetes?
Ans: I use the Rolling Update strategy. It updates application pods gradually instead of replacing all pods at once.
We can configure MaxSurge and MaxUnavailable. Readiness probes help ensure that new pods are ready before receiving traffic.
## Q9. How would you connect an application running in Azure to a backend in GCP and a database in AWS?
Ans: The application flow would be:
User → Azure Frontend → GCP Backend → AWS Database.
For private connectivity between the cloud providers, we can use Site-to-Site VPN or services such as AWS Direct Connect, Azure ExpressRoute, and Google Cloud Interconnect.
We also need to configure private DNS, firewall rules, Redis caching, and connection pooling.
## Q10. What is the difference between ALB and NLB?
Ans: ALB works at Layer 7 and is used for HTTP and HTTPS traffic. It supports host-based and path-based routing.
NLB works at Layer 4 and supports TCP, UDP, and TLS traffic. It provides high throughput, low latency, and static IP addresses.
## Q11. How do you configure a TLS certificate on an NLB?
Ans: We can configure a TLS listener on the Network Load Balancer and attach an ACM certificate to it.
## Q12. What is the difference between application rollback and database rollback?
Ans: Application rollback means reverting the application to its previous version.
Database rollback means reverting database changes. We should preferably use backward-compatible database migrations.
## Q13. What would you do if the database changes are not backward-compatible?
Ans: First, I would stop or isolate the application writes. If a reverse migration is available and tested, I would use it.
Otherwise, I would restore the database using RDS Point-in-Time Recovery. After validating the database, I would restore the previous application version and preserve the failed database.
## Q14. Suppose you took a database backup at 9 AM and deployed an application at 10 AM. The deployment failed, and you need the data available just before deployment. What would you do?
Ans: I would use RDS Point-in-Time Recovery to restore the database to 9:59 AM, just before the deployment.
I would restore it as a new database instance, validate the data, and preserve the failed database.
## Q15. What is the difference between NACL and NAT Gateway?
Ans: NACL is a stateless firewall that controls inbound and outbound traffic at the subnet level.
NAT Gateway allows instances in a private subnet to access the internet without allowing direct inbound connections initiated from the internet.
## Q16. How do you create 10 EC2 instances with different names using Terraform?
Ans: We can use the count argument to create 10 EC2 instances and count.index to assign different names.
provider "aws" {
  region = "ap-south-1"
}

resource "aws_instance" "example" {
  count         = 10
  ami           = "ami-xxxxxxxx"
  instance_type = "t2.micro"

  tags = {
    Name = "EC2-${count.index + 1}"
  }
}
