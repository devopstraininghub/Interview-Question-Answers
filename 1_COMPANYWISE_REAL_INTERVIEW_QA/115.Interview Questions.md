**Q7. How comfortable are you with Linux and troubleshooting bare-metal machines?**

**A:** I troubleshoot Linux bare-metal systems by checking CPU, memory, disk space, network issues, running processes, system logs and application logs.

I use tools and commands such as `top`, `vmstat`, `free`, `df` and `systemctl`.

**Q8. Suppose you deployed an application on a bare-metal Linux server and customers are experiencing latency. What is your thought process for troubleshooting?**

**A:** First, I check disk space, memory, the database, application processes, load balancer and network routing. I check whether the application processes are working correctly and use Linux metrics to understand the system health.

**Q9. How would you identify where the latency is occurring?**

**A:** I measure timestamps at each layer, including the load balancer, networking, application and downstream servers.

Then I compare the total request time with the application processing time and database query time.

I use access logs, application logs, CloudWatch, Prometheus and Grafana for tracing and monitoring.

**Q13. What does `df -h` do?**

**A:** It checks filesystem usage and shows whether the disk space is full.

**Q14. What does `free -m` do?**

**A:** It checks memory usage.

**Q15. Suppose `df -h` shows 100% disk usage, but you can account for only 60%. What could be happening?**

**A:** One common cause is deleted files that are still held open by a running process. The deleted file path may not be visible normally, but the disk space is still occupied.

I can use `lsof | grep deleted` to identify the process holding the deleted file. Then I can safely restart the relevant process and verify the disk space again.

**Q16. Does `copytruncate` help in this disk-space scenario?**

**A:** `copytruncate` is a log rotation option. It copies the current log file to a rotated file.

It does not directly fix files that have already been deleted but are still open by a process. Log rotation can release space when the process properly closes or reopens the old log file.

**Q17. What is a Security Group in AWS?**

**A:** A Security Group is a stateful virtual firewall attached to EC2 instances or network interfaces. It controls inbound and outbound traffic.

**Q18. What does stateful mean in a Security Group?**

**A:** Stateful means that when a request is allowed, the response traffic is automatically allowed without requiring a separate outbound rule for that response.

For example, if an HTTPS request is allowed, the response traffic is automatically allowed.

**Q19. At what level does a Security Group operate?**

**A:** It operates at the instance or network interface level.

**Q20. What about Network ACLs?**

**A:** Network ACLs are stateless firewalls associated with subnets. They control traffic entering and leaving the subnet.

We can configure separate inbound and outbound rules.

**Q21. What is a NAT Gateway?**

**A:** A NAT Gateway is a managed AWS service that allows resources in a private subnet to initiate outbound connections to the internet without giving them public IP addresses.

The NAT Gateway uses a public IP address.

**Q22. Explain the logical flow of a NAT Gateway.**

**A:** I have a VPC containing a private subnet with a private EC2 instance. The private subnet has a route table that directs internet-bound traffic to the NAT Gateway.

The NAT Gateway is placed in a public subnet, which has a route to the Internet Gateway. This allows the private EC2 instance to access the internet through the NAT Gateway.

**Q23. Suppose an EC2 instance needs to read data from an S3 bucket. How would you provide access?**

**A:** I create an IAM role with only the required S3 permissions and attach that role to the EC2 instance through an instance profile.

The application receives temporary credentials without storing access keys.

**Q24. Suppose an EC2 instance is in a private subnet and cannot run `apt update`. How would you troubleshoot it?**

**A:** First, I confirm the instance's private IP address. Then I check the subnet route table to verify whether routing is correct.

I also check the Security Groups and Network ACLs for any mismatches. I verify internet access for the private subnet through the route table and check whether the required ports are working.

I test the issue directly from the instance.

**Q25. Do you need to check DNS resolution in this situation?**

**A:** Yes. I check DNS resolution because `apt update` needs to resolve repository names.

If DNS fails, I check the VPC settings for DNS resolution and DNS hostnames.

**Q26. What is a VPC endpoint?**

**A:** A VPC endpoint provides private access from resources inside a VPC to supported AWS services.

For example, an EC2 instance in a private subnet can access an S3 bucket through an S3 VPC endpoint.

**Q27. Explain the flow of accessing S3 with and without a VPC endpoint.**

**A:** Without an S3 endpoint, the flow is:

Private EC2 instance → Private subnet → NAT Gateway → Internet Gateway → S3 bucket.

With an S3 VPC endpoint, the private EC2 instance accesses S3 through the VPC endpoint using the route table. The traffic does not need to go through the NAT Gateway and Internet Gateway.

It is more secure and can reduce NAT Gateway costs.

**Q28. A customer reports a 502 or 504 error from an Application Load Balancer. How would you troubleshoot it?**

**A:** First, I identify whether the errors are coming from the load balancer or the target applications.

I check the Elastic Load Balancer metrics in CloudWatch. I look at the metrics showing connection establishment and responses from the target group. If there is an issue with the targets, I investigate and resolve it accordingly.

**Q29. What is AWS CloudWatch used for?**

**A:** CloudWatch is an AWS monitoring and observability service. It collects metrics, logs and events. We can also configure alarms for AWS resources and applications.

**Q36. What is a Terraform module?**

**A:** A Terraform module is a reusable collection of Terraform configuration files. It groups resources, variables and outputs for infrastructure.

We can use the same infrastructure pattern across multiple environments.

**Q37. What is Terraform bootstrapping? Why is it called the chicken-and-egg problem?**

**A:** Terraform bootstrapping means creating the infrastructure required to manage Terraform itself.

For example, Terraform needs a remote S3 bucket to store its state file and DynamoDB for state locking. But Terraform also needs to create those resources.

The problem is that Terraform cannot use the remote backend before the backend resources already exist.

**Q38. Where do you store the bootstrap state?**

**A:** The bootstrap state is maintained separately from the main infrastructure state. I have used S3 for storing the state.
