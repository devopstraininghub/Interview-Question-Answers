**Q5. Suppose applications in the cluster intermittently fail to resolve services. How do you investigate the issue?**

**Answer:** I would identify whether the DNS issue affects specific pods, nodes, or the entire cluster.

I would test DNS resolution from the affected pods using `nslookup` with the service name, namespace, and service cluster information.

Next, I would check the CoreDNS pod status using `kubectl get pods` in the `kube-system` namespace.

I would check the CoreDNS logs for DNS timeouts, errors, or failed queries.

I would also verify CoreDNS services, endpoints, and ConfigMaps for configuration issues.

Finally, I would check network policies, port 53 connectivity, and node networking.

**Q10. Do you know what PV and PVC are?**

**Answer:** Yes. I understand PV and PVC in Kubernetes.

PV stands for Persistent Volume, which represents the storage available to the Kubernetes cluster.

PVC stands for Persistent Volume Claim, which is used to request storage for an application.

**Q11. What's the difference between StatefulSet and Deployment?**

**Answer:** The main difference between StatefulSet and Deployment is that a Deployment manages stateless applications, whereas a StatefulSet manages stateful applications.

**Q12. Do you know the difference between an orphan process and a zombie process?**

**Answer:** Yes. I understand both concepts in Linux process management.

An orphan process is a process whose parent has been terminated while the child process is still running. Linux assigns the orphan process to PID 1 or another designated process to manage it.

A zombie process is a process that has completed execution, but its parent has not collected its exit status.
